# 游泳打卡网页：部署与维护说明

本文件面向负责配置网页的人。普通用户的打卡规则在网页首次开卡前的“使用说明”中；开卡或导入开卡信息后，该入口自动隐藏。

## 1. 方案与文件

- 网页：静态 HTML，部署在 GitHub Pages。
- 云端数据：单独的 GitHub 私有仓库，固定文件为 `swim-data.json`。
- 本机数据：浏览器 IndexedDB，保存共享记录缓存、待同步操作和此设备的界面偏好。
- 授权：两台手机首次使用时输入同一个受限 GitHub Token。华为用户不需要 GitHub 账号。
- 不使用数据库，也不需要同步中转接口。网页直接调用 GitHub API。

**网页可以公开，数据仓库必须私有。** 密钥不写进 HTML。仅持有网址的人不能通过本网页读取私有仓库记录。

## 2. 发布网页

1. 先从旧网页导出完整 JSON，另存一份，不要修改或覆盖原备份。
2. 创建用于网页的 GitHub 仓库，把更新后的 HTML 作为 `index.html` 上传。
3. 在仓库 `Settings → Pages` 选择发布来源，例如 `Deploy from a branch`，分支 `main`，目录 `/ (root)`。
4. 发布后访问 Pages 提供的 HTTPS 地址。此版本的同步功能只在 HTTPS 且主机名以 `.github.io` 结尾时启用；自定义域名和其他托管平台需要调整网页的部署检查逻辑。
5. iPhone 用 Safari 打开网址，不再依赖快捷指令“显示网页视图”；可添加到主屏幕。华为用现代浏览器打开同一个网址，可添加书签或桌面快捷方式。
6. 用两台手机分别测试 Wi-Fi、移动网络以及实际 GitHub API 连通性。电脑可访问不代表两台手机都能稳定连接。

文件预览、聊天预览或不满足上述域名条件的环境不启用 GitHub 同步。本地功能是否可用还取决于浏览器是否允许 IndexedDB。

## 3. 创建私有数据仓库

1. 另外创建一个私有仓库，例如 `swim-private-data`。
2. 创建时勾选添加 README，确保 `main` 分支已初始化。
3. 不要把真实备份、共享数据文件或 Token 放到公开网页仓库。
4. 无需手动创建 `swim-data.json`，首次成功同步会创建它。
5. 两台手机的 GitHub 用户名、仓库名和分支必须相同。

网页在同步前检查数据仓库是否私有。若为公开仓库，将拒绝上传。

## 4. 创建并配置 Token

由有 GitHub 账号的人操作：

1. 打开 GitHub `Settings → Developer settings → Personal access tokens → Fine-grained tokens`。
2. 创建细粒度 Token，只选择游泳私有数据仓库。
3. 授予该仓库 `Contents: Read and write` 权限，不授权其他仓库或工作流等无关功能。
4. 设置有效期，按 GitHub 当前页面完成创建。
5. 仅在两台手机网页标题右侧的“GitHub 设置”中输入，不放入聊天、网址参数、HTML 或备份文件。

网页表单填写仓库拥有者用户名、私有仓库名称、分支和 Token。已配置 Token 时，密码框留空表示不更换。

- 勾选“记住此设备上的 Token”：保存在该浏览器 IndexedDB，刷新后可继续使用；它不是加密保险箱，设备访问者、网页漏洞等仍可能造成凭证泄露。
- 不勾选：Token 只保留在当前页面内存，刷新或重新打开后需要输入。
- “移除本机 Token”只清除此设备的授权信息，不删除打卡记录，也不会撤销 GitHub 上的 Token。
- Token 失效、过期或泄露后，在 GitHub 撤销或更换，并在两台手机重新配置。

两个人共用同一个 Token，具备相同的仓库权限。网页中的成员选择只用于标记操作，不是安全身份认证；GitHub 端请求归属于 Token 所属账号。知道 Token 的人可以绕过网页直接修改其权限范围内的仓库文件。

**切换仓库前先导出备份。** 切换仓库或分支会把当前本机操作历史作为待同步项，尝试合并到新目标；不是自动切换到一个空白账号。

## 5. 旧备份迁移及界面偏好

网页支持旧版 JSON 和新版操作历史备份。导入采取合并，不是简单覆盖整份本机数据。

旧备份中的字段处理如下：

| 旧字段 | 新版处理 |
| --- | --- |
| `startDate`、`totalFee` | 导入开卡日期和每人卡费 |
| `users.A.checkins`、`users.B.checkins` | 导入两人的打卡记录 |
| `suspendRecords` | 导入停卡开始日和恢复日 |
| `darkMode` | 不再作为共享业务数据导入；外观改为本机 `prefs.theme`，默认跟随系统 |
| `currentUser` | 不再作为共享业务数据导入；当前成员改为本机 `prefs.user`，默认 A，可在页面切换 |
| `lastAutoBackupMonth` | 不再使用，新版取消旧的“每月首次打卡弹窗备份”逻辑 |

**原 JSON 保留这三个旧字段也可以，无需手动删除。** 导入时忽略它们，不影响打卡记录。外观和当前成员需要各自在设备上选择；它们不随云端同步，也不包含在新版业务备份里。

如两台设备各有旧记录，先分别导出，逐份导入并检查结果。旧版同一成员、同一日期的打卡合并；相同起止日期的旧版停卡使用同一记录编号。不同起止日期的重叠停卡仍需人工检查。旧时间戳按导入设备的本地日期转换，跨时区迁移时核对日历。

新版备份包含开卡设置和删除 / 重置操作。导入可能改变已有数据，不应把旧备份当作纯粹新增记录。新导入的开卡设置也可能影响有效期。

## 6. 同步流程与冲突

1. 修改和待同步操作先一起保存到本机，成功后才更新页面。
2. 从 GitHub API 读取最新数据和文件 `sha`。
3. 按唯一操作 ID 去重，合并云端操作历史与本机待同步项。
4. 携带当前 `sha` 上传；版本冲突时重新读取、合并，单次最多尝试三轮。
5. GitHub 确认后移除已上传的待同步项。若上传成功但响应丢失，下次读取可按操作 ID 去重。

触发时机：首次打开、数据修改、页面回到前台、网络恢复以及点击“同步”。临时网络失败在前台约一分钟后重试。权限、配置或数据错误需处理后再试，不持续高频重试。无持续实时轮询，另一台手机需打开、回前台或点击同步才能获取更新。

- 不同成员 / 不同日期的打卡合并。
- 同一条记录或字段按云端操作追加顺序处理，后提交的操作生效，不依赖两台手机的时钟一致。
- 删除使用明确的删除操作，避免只从本地数组移除。
- 双方都修改开卡设置时，网页要求确认后再提交本机设置。
- 合并后若停卡额度、重叠日期或打卡有效范围不符合规则，暂停上传并保留待同步项，先备份再修正。
- 重置是一条共享操作，不是 GitHub 历史清除；另一设备之后上传的离线修改仍可能重新出现。

本机同一时间建议只在一个标签页中编辑，避免多个标签页使用不同的内存状态。本机持久化写入失败时，不确认新修改，避免误认为已保存。

## 7. 离线、备份及安全边界

- 已打开的网页可断网记录，待同步项保留在本机。
- 本版不包含 Service Worker 或离线启动缓存，**不保证断网重新打开网页**。首次访问需要联网。
- 关闭网页、锁屏或系统暂停浏览器后，**不保证继续后台上传**；下次打开或操作时再次尝试。
- 浏览器清理网站数据、删除 App、更换浏览器 / 设备会影响本地缓存、界面偏好、保存的 Token 及未上传记录。
- 定期使用导出按钮保留完整 JSON 文件。本地 IndexedDB 不是永久文件备份。
- 导出包含共享记录和待同步操作，不包含 Token 或仓库设置。
- iPhone 可尝试系统分享；浏览器不支持 JSON 分享时，使用下载或复制完整备份文本。取消分享不会强制下载。
- GitHub 提交历史可能保留已删除记录；网页重置不代表从 Git 历史中永久擦除。
- 页面无第三方脚本依赖。网络请求只携带访问该仓库所需的授权信息，不向其他服务上传记录。
- 自动处理的安全上限：最多 10,000 条操作，云端文件约 950,000 字节。达到上限后先备份，停止自动上传；没有自动压缩或历史清理机制。

## 8. 常见问题

| 状态或问题 | 处理方式 |
| --- | --- |
| 有待同步项 | 保留本机数据，联网后点同步或下次打开继续尝试 |
| 401 / Token 过期 | 更换 Token，记录不会因此自动清空 |
| 403 / 429 | 检查 Token 的仓库授权和 Contents 权限；可能限流，稍后再试 |
| 仓库 / 分支找不到 | 核对用户名、仓库名、Token 授权；确保目标分支已初始化 |
| 云端 JSON 不支持 / 无法解析 | 不会覆盖该文件；先备份并检查格式，新版同步文件需要 `schemaVersion: 2` 和 `ops` |
| 文件预览不能同步 | 改用部署后的 HTTPS GitHub Pages 地址 |
| 不记住 Token 后刷新不能同步 | 属于预期行为，重新输入 Token |
| 导入后没有使用说明按钮 | 已有开卡信息时自动隐藏，属于预期行为 |

## 9. 页面布局与验证范围

标题右侧为 GitHub 设置、同步按钮和小字状态，不显示技术配置提示或同步副标题。底部按旧页面顺序保留“📥导入JSON / 重置数据 / 📤导出记录”。设置表单保留必要字段，部署说明集中在本文件。

代码已进行语法与核心数据逻辑检查；未连接实际仓库，也未在真实 iPhone / 华为设备上完成端到端验证。正式迁移前，请使用测试数据在两台手机验证登录授权、并发打卡、离线恢复、删除、导入和导出，确认无误后再导入原始记录。
